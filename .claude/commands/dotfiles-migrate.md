# dotfiles 移行コマンド

別の端末で行った移行作業（`migrations/*.md`）のうち、この端末にまだ適用されていないものを順に実行します。

## 実行フロー

### Step 1: dotfiles リポジトリの特定と更新

`~/.Brewfile` は dotfiles の `Brewfile` へのシンボリックリンクなので、そこからリポジトリの場所を特定します。

```bash
DOTFILES_DIR="$(dirname "$(readlink ~/.Brewfile)")"
git -C "$DOTFILES_DIR" status --short
git -C "$DOTFILES_DIR" branch --show-current
```

- 未コミットの変更がある場合は内容をユーザーに見せ、続けてよいか確認する
- `master` にいて差分がなければ `git -C "$DOTFILES_DIR" pull` を実行する（別ブランチなら pull するかユーザーに確認する）
- pull 後は `"$DOTFILES_DIR/install.sh"` を実行し、新しく増えたリンク（コマンドファイルなど）を張る

### Step 2: 移行の一覧と適用状況の判定

`$DOTFILES_DIR/migrations/` にある `YYYY-MM-DD-*.md` を**ファイル名順**にすべて読みます（`README.md` と `_` で始まるファイルは除く）。

各ファイルの「完了チェック」のコマンドを実行し、次のように分類して一覧表で提示します。

- ✅ 適用済み: 完了チェックがすべて期待どおり
- ⬜ 未適用: 期待どおりでないチェックがある（どれが期待と違ったかも示す）
- ❓ 判定不能: この端末に該当しない、またはチェックが実行できない（理由を示す）

### Step 3: 未適用の移行を実行

未適用のものがなければ「すべて適用済み」と伝えて終了します。

未適用のものがある場合は、実行する移行と手順の概要を示して**ユーザーの確認を取ってから**、古い順に1件ずつ実行します。

- 手順は移行ファイルに書かれたとおりに実行する。端末の状態が想定と違う場合は、自己判断で進めずに状況を報告して指示を仰ぐ
- パッケージのアンインストールやファイル削除など元に戻しにくい操作は、実行前に対象を確認する
- 手順の途中で `~/.zshrc` などリンク先のファイルが書き換わった場合は `git -C "$DOTFILES_DIR" diff` で差分を確認し、意図しない変更は報告する
- 1件終わるごとに「確認」セクションのコマンドを実行し、結果を報告してから次へ進む

### Step 4: 結果の報告

- 各移行の結果（適用した / スキップした / 失敗した）
- 再起動が必要なもの（ターミナルの開き直し、Claude Code の起動し直しなど）や、ユーザーが手動で行う後片付け
- `git -C "$DOTFILES_DIR" status --short` の結果（移行作業でリポジトリに差分が出ていないか）

## 注意事項

- `~/.config/` や `~/.claude/` をディレクトリごと移動・削除・リンクしない（CLAUDE.md のインシデント参照）
- 移行ファイルの手順が古くなっていて実行できなかった場合は、ファイルの修正案も合わせて提示する
